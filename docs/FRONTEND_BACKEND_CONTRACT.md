# Frontend / Backend Contract

> **Contract version: 0.2.0 (draft)**. This is the most important shared document.
> The TypeScript interfaces here are **canonical**. [DATA_MODELS.md](DATA_MODELS.md) explains each model and gives examples and must always agree with this file.
> Any change follows the process in [DEVELOPMENT_OWNERSHIP.md](DEVELOPMENT_OWNERSHIP.md#changing-the-contract).

This contract is the boundary between two independent implementations. The frontend developer can build against mock responses that follow these shapes; the backend implements the same operations against real data later. How either side is structured internally is up to its owner.

## 1. Conventions

| Topic | Rule |
|---|---|
| Base path | `/api/v1` |
| Format | JSON (`Content-Type: application/json`), UTF-8. Images are fetched from URLs returned in JSON, not embedded. |
| Field names | `camelCase` |
| Timestamps | ISO 8601 in UTC with `Z`, e.g. `2025-07-14T03:22:10Z` |
| Coordinates | ICRS, decimal degrees: `raDeg` in [0, 360), `decDeg` in [-90, 90] |
| Wavelength | micrometres, field names end in `Um` |
| IDs | Opaque strings. The frontend must never parse or construct them. |
| Optional fields | **Omitted when absent. Never `null`.** `undefined`/missing means "not available". |
| Arrays | Always present; empty array means "none". |
| Unknown enum values | Frontend should tolerate unknown string values by showing them verbatim and not crashing. |
| Auth | None for v0.1 (OD-7). |
| Units | Every numeric measurement carries an explicit unit string. No implicit units. |

### Provenance rule

Every field in a model is one of:
- **source**: copied or normalized from NASA/IRSA metadata or files.
- **derived**: computed by our backend.
- **app**: identifiers/records generated by our app (IDs, timestamps of our own actions).

[DATA_MODELS.md](DATA_MODELS.md) labels every field. The contract never promises that a given IRSA field exists. Where source metadata may be missing, the field is optional, and the raw source values are available in `sourceMetadata` (an untyped passthrough that the frontend may display but must not depend on).

## 2. Shared types

```ts
export type ISODateTime = string;   // e.g. "2025-07-14T03:22:10Z"
export type Id = string;            // opaque

export interface SkyCoordinate {
  raDeg: number;                    // ICRS
  decDeg: number;                   // ICRS
}

/** Every resource that can be slow, missing, or failed carries this. */
export type AvailabilityStatus =
  | "available"     // data present and usable
  | "processing"    // backend is working; poll the same GET again
  | "unavailable"   // does not exist or is not provided by the archive (not an error)
  | "failed";       // backend attempted and failed

export interface Availability {
  status: AvailabilityStatus;
  /** Human-readable. Present whenever status !== "available". */
  statusReason?: string;
  /** Present when status === "failed" or "processing"; may be retried. */
  retryAfterSeconds?: number;
}

export interface QualityFlag {
  /** Stable identifier. For origin "source" this mirrors the archive's flag name/bit as reported; do not assume it is a fixed list. */
  code: string;
  severity: "info" | "warning" | "critical";
  description: string;
  origin: "source" | "derived";
}
```

## 3. Models

Full field-by-field explanations: [DATA_MODELS.md](DATA_MODELS.md).

```ts
export interface AstronomicalObject {
  objectId: Id;                          // app
  name: string;                          // primary display name
  aliases: string[];
  coordinates: SkyCoordinate;
  objectType?: string;                   // free-text from resolver, e.g. "Galaxy"; not a closed enum
  properMotion?: ProperMotion;           // catalogue value if available (see ProperMotion)
  resolver: { name: string; identifier?: string }; // where name/coords came from
  observationSummary?: {                 // derived; omitted if not computed yet
    count: number;
    firstObservedAt?: ISODateTime;
    lastObservedAt?: ISODateTime;
  };
}

export interface Observation {
  observationId: Id;                     // app-stable
  objectIds: Id[];                       // objects this observation covers (may be empty)
  irsaObservationId?: string;            // identifier as used by IRSA, if one exists
  dataRelease?: string;                  // release identifier as reported by the archive
  observedAt?: ISODateTime;              // start of exposure, if the archive provides it
  center: SkyCoordinate;
  footprint?: SkyCoordinate[];           // polygon corners, if derivable
  detector?: string;                     // as reported, if available
  bandpass?: string;                     // archive bandpass name as reported; lets clients group same-band frames
  wavelengthRangeUm?: { min: number; max: number }; // range covered by this image, if derivable
  image: Availability;                   // availability of the viewable image
  qualityFlags: QualityFlag[];
  qualitySummary: "good" | "degraded" | "poor" | "unknown"; // derived
  sourceMetadata?: Record<string, unknown>; // raw archive values, untyped, display-only
}

export interface WcsSummary {
  ctype1?: string; ctype2?: string;
  crval: [number, number];
  crpix: [number, number];
  cd: [[number, number], [number, number]];
  pixelScaleArcsec?: number;
  /** True if the full solution has terms (e.g. distortion) not captured here. Use the pixel-to-sky endpoint for precise coordinates. */
  approximate: boolean;
}

export interface ObservationImage {
  observationId: Id;
  availability: Availability;
  imageUrl?: string;                     // display-ready raster (PNG/WebP). Required if availability.status === "available"
  width?: number;                        // pixels of imageUrl
  height?: number;
  stretch?: {
    mode: "linear" | "log" | "sqrt" | "asinh";
    lowValue: number;                    // data value mapped to black
    highValue: number;                   // data value mapped to white
    unit?: string;
  };
  wcs?: WcsSummary;                      // maps pixels of imageUrl to sky (approximate)
  qualityMaskUrl?: string;               // optional transparent overlay marking flagged pixels
  fitsDownloadUrl?: string;              // optional raw file download; frontend does not parse it
  /** Images requested with the same grid parameters share one pixel grid and have equal gridId (see "Common pixel grid"). */
  gridId?: string;
  generatedAt: ISODateTime;              // app
}

export interface SpectralPoint {
  wavelengthUm: number;                  // band centre
  wavelengthMinUm?: number;
  wavelengthMaxUm?: number;
  bandIndex?: number;                    // 1-based index among the mission's bands, if mappable
  available: boolean;                    // false => gap; flux omitted
  unavailableReason?: string;
  flux?: number;                         // in SpectralData.fluxUnit
  fluxUncertainty?: number;              // same unit; basis in SpectralData.uncertaintyBasis
  qualityFlags: QualityFlag[];
  observationId?: Id;                    // observation this point came from
  observedAt?: ISODateTime;
}

export interface SpectralData {
  spectrumId: Id;
  objectId: Id;
  availability: Availability;
  position: SkyCoordinate;               // where the spectrum was extracted
  apertureRadiusArcsec?: number;
  extractionMethod: string;              // short description of how points were produced
  wavelengthUnit: "um";
  fluxUnit: string;
  uncertaintyBasis?: string;             // how fluxUncertainty was obtained, e.g. "propagated from archive uncertainty plane"
  points: SpectralPoint[];               // ordered by wavelengthUm; may include unavailable points
  expectedBandCount?: number;            // number of bands the mission defines (reference for gap display)
  warnings: string[];
  generatedAt: ISODateTime;
}

export interface Measurement {
  measurementId: Id;
  kind: "aperture_flux" | "flux_change" | "angular_separation" | "region_statistics" | "position_centroid" | "derived_motion";
  value: number;
  unit: string;
  uncertainty?: number;                  // same unit as value
  uncertaintyBasis?: string;
  observationIds: Id[];                  // inputs
  region?: { center: SkyCoordinate; radiusArcsec: number };
  method: string;                        // short description including key parameters
  qualityFlags: QualityFlag[];
  warnings: string[];
  createdAt: ISODateTime;
}

export type CheckResult = "pass" | "warn" | "fail" | "notEvaluated";

export interface CompatibilityCheck {
  name: "wavelength" | "calibration" | "alignment" | "quality" | "dataRelease" | "footprint" | "background";
  result: CheckResult;
  detail: string;
}

export interface ComparisonResult {
  comparisonId: Id;
  mode: "blink" | "overlay" | "difference";
  baseObservationId: Id;
  targetObservationId: Id;
  /** "same_band_epochs": same bandpass at different times (temporal). "cross_band": different bands (spectral, NOT a time change). */
  comparisonKind?: "same_band_epochs" | "cross_band";
  availability: Availability;
  compatibility: {
    verdict: "comparable" | "comparable_with_caveats" | "not_comparable" | "unknown";
    checks: CompatibilityCheck[];
  };
  alignment?: { method: string; residualArcsec?: number };
  /** Images resampled onto a common pixel grid so blink/overlay line up. Present when availability.status === "available" and the verdict is not "not_comparable". */
  baseImage?: ObservationImage;
  targetImage?: ObservationImage;
  differenceImage?: ObservationImage;    // only for mode "difference"
  measurements: Measurement[];
  warnings: string[];
  createdAt: ISODateTime;
}

/** Total proper motion with provenance. `value`/`unit`/`source` are the display fields; the rest is optional detail. */
export interface ProperMotion {
  value: number;                         // total proper motion
  unit: string;                          // e.g. "arcsec/yr"; always stated
  source: string;                        // human-readable origin, e.g. a catalogue name
  /** Where the number comes from. Catalogue values and values derived by our app are never mixed. */
  provenanceKind: "catalog" | "derived_from_observations" | "unvalidated_displacement";
  catalogName?: string;
  catalogId?: string;
  pmRaMasPerYr?: number;                 // whether this includes cos(dec) is stated in `convention`
  pmDecMasPerYr?: number;
  convention?: string;
  referenceEpoch?: string;               // as stated by the source
  uncertainty?: number;                  // same unit as `value`
}

/** A source worth a closer look. A ranking for human follow-up, NOT a detection and NOT validation. */
export interface Candidate {
  candidateId: Id;                       // app; stable for the same object + field + method version
  label: string;                         // short human-readable tag, e.g. "SX-0017"
  objectId?: Id;
  observationIds: Id[];                  // observations it is based on (>= 2 for motion)
  kind: "positional_change" | "brightness_change" | "both";
  description: string;                   // plain-language summary, backend-generated
  evidence: string[];                    // display text
  evidenceRefs?: AIReference[];          // optional links to the stored results behind the evidence
  /** One entry per observation, in `observationIds` order, so a client can draw a track without computing anything. */
  track: { observationId: Id; sky: SkyCoordinate; pixel?: { x: number; y: number } }[];
  motion?: { value: number; unit: string; uncertainty?: number; method: string };
  properMotion?: ProperMotion;           // catalogue value for this source, if known
  /** Ranking heuristic in [0, 1]. NOT a probability. Always shown with scoreBasis. */
  score: number;
  scoreBasis: string;
  isProbability: false;                  // literal
  qualityFlags: QualityFlag[];
  warnings: string[];
  limitations?: string[];                // what was not validated (calibration, blending, ...)
  status: "candidate";                   // literal; the API never reports "confirmed"
  createdAt: ISODateTime;
}

export interface Note {
  noteId: Id;
  text: string;
  createdAt: ISODateTime;
  observationId?: Id;
  comparisonId?: Id;
}

export interface Bookmark {
  bookmarkId: Id;
  targetType: "object" | "observation" | "comparison" | "spectrum" | "measurement" | "candidate";
  targetId: Id;
  label?: string;
  createdAt: ISODateTime;
}

export interface InvestigationEvent {
  eventId: Id;
  type: "object_opened" | "observation_viewed" | "comparison_created" | "spectrum_viewed" | "measurement_created";
  targetId?: Id;
  at: ISODateTime;
}

export interface ChatContext {
  activeView?: "viewer" | "timeline" | "comparison" | "spectrum" | "workspace";
  candidateId?: Id;
  /** Hint for explanation depth; the backend may ignore it. */
  mode?: "beginner" | "advanced";
  objectId?: Id;
  observationIds?: Id[];
  comparisonId?: Id;
  spectrumId?: Id;
  measurementIds?: Id[];
  /** A point/region the user has selected in an image. */
  selection?: { observationId: Id; sky?: SkyCoordinate; radiusArcsec?: number };
}

export interface ChatMessage {
  messageId: Id;
  role: "user" | "assistant";
  content: string;
  createdAt: ISODateTime;
  context?: ChatContext;                 // set on user messages
}

export interface AIReference {
  targetType: "observation" | "comparison" | "spectrum" | "measurement" | "object" | "candidate";
  targetId: Id;
}

export interface SuggestedAction {
  kind: "open_observation" | "open_comparison" | "open_spectrum" | "add_note" | "run_comparison";
  label: string;
  targetId?: Id;                         // for run_comparison: ignored; use params
  params?: Record<string, string | number>;
}

export interface AIResponse {
  message: ChatMessage;                  // role "assistant"; content is AI-generated explanation
  references: AIReference[];             // results the explanation is based on
  caveats: string[];                     // limitations the user should see next to the answer
  suggestedActions: SuggestedAction[];
  availability: Availability;            // "unavailable" if the AI backend is down; message then explains
}

export interface Investigation {
  investigationId: Id;
  title: string;
  objectId?: Id;
  createdAt: ISODateTime;
  updatedAt: ISODateTime;
  notes: Note[];
  bookmarks: Bookmark[];
  history: InvestigationEvent[];
  /** Server-managed. Ignored on PUT; changed only via POST /chat/messages. */
  messages: ChatMessage[];
}

/** Request body for create/update. */
export type InvestigationInput = Pick<Investigation, "title" | "objectId" | "notes" | "bookmarks" | "history">;
```

```ts
export interface Page<T> {
  items: T[];
  total: number;
  limit: number;
  offset: number;

export interface ApiError {
  error: {
    code:
      | "INVALID_REQUEST"      // 400
      | "NOT_FOUND"            // 404
      | "UPSTREAM_UNAVAILABLE" // 502/503 (IRSA, resolver)
      | "DATA_UNAVAILABLE"     // 404/422 used only when no resource-level availability field exists
      | "PROCESSING_FAILED"    // 500
      | "AI_UNAVAILABLE"       // 503
      | "RATE_LIMITED"         // 429
      | "INTERNAL";            // 500
    message: string;           // safe to show to the user
    retryable: boolean;
    details?: Record<string, unknown>; // for debugging, not for display
    requestId?: string;
  };
}
```

## 5. Endpoints

All paths are under `/api/v1`. Query parameters are strings on the wire.

| # | Operation | Method & path | Request | Response |
|---|---|---|---|---|
| 1 | Search objects | `GET /objects/search` | `q` (required), `limit` (default 10, max 50) | `Page<AstronomicalObject>` |
| 2 | Resolve one name/coordinates | `GET /objects/resolve` | `q` (name) **or** `ra` + `dec` (deg) | `AstronomicalObject` |
| 3 | Get object | `GET /objects/{objectId}` | n/a | `AstronomicalObject` |
| 4 | List observations of an object | `GET /objects/{objectId}/observations` | `from`, `to` (ISO date), `dataRelease`, `minWavelengthUm`, `maxWavelengthUm`, `limit` (default 50, max 200), `offset`, `sort` = `observedAt` or `-observedAt` (default `observedAt`) | `Page<Observation>` |
| 5 | Get observation | `GET /observations/{observationId}` | n/a | `Observation` |
| 6 | Get observation image | `GET /observations/{observationId}/image` | `stretch` (`linear`\|`log`\|`sqrt`\|`asinh`, default `asinh`), `lowPercentile`, `highPercentile`, optional field of view: `centerRa`, `centerDec` (deg; default the object centre), `fovArcmin` | `ObservationImage` |
| 7 | Pixel to sky | `GET /observations/{observationId}/pixel-to-sky` | `x`, `y` (pixels of the image returned in #6) | `{ sky: SkyCoordinate }` |
| 8 | Create comparison | `POST /comparisons` | `{ baseObservationId, targetObservationId, mode }` | `ComparisonResult` (status 200 if finished, 202 if `processing`) |
| 9 | Get comparison | `GET /comparisons/{comparisonId}` | n/a | `ComparisonResult` |
| 10 | Get spectrum | `GET /objects/{objectId}/spectrum` | optional `ra`, `dec`, `apertureRadiusArcsec` (defaults to the object's position) | `SpectralData` (200 or 202) |
| 11 | Create measurement | `POST /measurements` | `{ kind, observationIds, region? }` | `Measurement` |
| 12 | Send chat message | `POST /chat/messages` | `{ investigationId?, message, context }` | `AIResponse` |
| 13 | List investigations | `GET /investigations` | `limit`, `offset` | `Page<Pick<Investigation, "investigationId"\|"title"\|"objectId"\|"updatedAt">>` |
| 14 | Create investigation | `POST /investigations` | `InvestigationInput` | `Investigation` (201) |
| 15 | Get investigation | `GET /investigations/{investigationId}` | n/a | `Investigation` |
| 16 | Update investigation | `PUT /investigations/{investigationId}` | `InvestigationInput` (full replace; `messages` ignored) | `Investigation` |
| 17 | Delete investigation | `DELETE /investigations/{investigationId}` | n/a | 204, no body |
| 18 | Health | `GET /health` | n/a | `{ status: "ok", contractVersion: string }` |
| 19 | List candidates | `GET /objects/{objectId}/candidates` | `limit` (default 20), `offset`, `minScore`, `sort` = `-score` (default) or `score` | `Page<Candidate>` |

### Semantics worth being explicit about

- **Image delivery.** `GET .../image` returns metadata and a URL. The backend renders the display raster. The frontend draws the raster and never opens FITS. `imageUrl` is fetched with a normal `<img>`/canvas load and needs no special headers. (Tiling/size policy: OD-5.)
- **Common pixel grid.** The backend resamples each image onto a north-up grid centred on `centerRa/centerDec`, sized by `fovArcmin`, with a fixed pixel scale, and returns the same `gridId` for every image requested with the same parameters. So blinking through observations and drawing `Candidate.track[].pixel` markers need no client-side alignment. There is no separate "frame sequence" operation.
- **Stretch.** The backend applies the stretch. The frontend changes it by re-requesting `/image` with different parameters. Any purely cosmetic client-side adjustment is the client's business; it is not a measurement.
- **Pixel coordinates.** `x`,`y` are pixel positions in the raster at `imageUrl`, origin top-left. The authoritative mapping to sky is #7; `wcs` is a convenience and may be approximate.
- **Comparison alignment.** For `blink` and `overlay`, `baseImage` and `targetImage` share one pixel grid so the frontend can stack them without further math.
- **Async work.** If a resource is not ready, the response is HTTP `202` with a body whose `availability.status` is `"processing"`. The frontend polls the matching `GET` (#9, #10) every `retryAfterSeconds` (default 2) until the status changes. No other job mechanism exists.
- **Chat persistence.** If `investigationId` is given, the backend appends the user message and the assistant message to `Investigation.messages`. The frontend may also render them from the `AIResponse` directly.
- **Idempotency.** `PUT` and `DELETE` are idempotent. `POST` operations are not. Concurrent edits: last write wins (OD-15).

## 6. Error handling

- Non-2xx responses use the `ApiError` envelope.
- **"No data" is not an error.** Absence is represented in the data (see §8). Use errors only when the request itself cannot be served.
- HTTP mapping: 400 `INVALID_REQUEST`, 404 `NOT_FOUND`, 429 `RATE_LIMITED`, 500 `PROCESSING_FAILED`/`INTERNAL`, 502/503 `UPSTREAM_UNAVAILABLE`/`AI_UNAVAILABLE`.
- `message` is always user-safe. The frontend shows `message` and offers retry when `retryable` is true.
- A request that gets no response at all (network failure) has no `ApiError`; clients must treat it as a separate case.

## 7. Loading states

The contract defines **resource state** only: `Availability.status`. `processing` means the request succeeded but the data is not ready; clients poll the same `GET` (see §5, "Async work"). A successful HTTP response can carry a resource that is `processing`, `unavailable`, or `failed`, and clients must expect all four statuses on every resource that carries `availability`. Client-side request/loading state is the frontend's own concern and is not specified here.

## 8. Representing missing or unavailable data

| Situation | Representation |
|---|---|
| Object has no SPHEREx observations | `GET .../observations` → 200, `items: []`, `total: 0`, `coverageNote` explains |
| Observation exists but image cannot be produced | `Observation.image.status = "unavailable"`; `GET .../image` → 200 with `availability.status = "unavailable"`, no `imageUrl` |
| Image generation failed | `availability.status = "failed"`, `statusReason`, `retryAfterSeconds` |
| Archive did not provide a field (e.g. no observation time) | Field omitted |
| Spectrum band has no usable observation | `SpectralPoint.available = false`, `flux` omitted, `unavailableReason` set |
| Comparison not scientifically valid | 200, `compatibility.verdict = "not_comparable"`, failing `checks`; images/difference omitted |
| Upstream archive unreachable | HTTP 502/503 `UPSTREAM_UNAVAILABLE` |
| Unknown ID | HTTP 404 `NOT_FOUND` |
| Uncertainty not available | `uncertainty` omitted; UI must not show a fabricated error bar |
| AI backend down | 503 `AI_UNAVAILABLE` or 200 with `AIResponse.availability.status = "unavailable"` (backend picks one and documents it, OD-9) |

## 9. Mock conformance

Mocks are written and structured by the frontend developer. The only requirements:

- Mock responses are valid instances of the types in §3 and use the same request/response shapes as §5.
- Mock data lives in the frontend implementation only, never in the backend.
- Mock IDs and values must not be presented as real NASA data without labeling.
- For coverage, the contract defines these states, so mocks and the backend should both be able to represent them: empty result list, `processing`, `unavailable`, `failed`, `not_comparable`, spectrum with gaps, observation with quality flags, AI unavailable.

## 10. Backend contract-test requirement (backend-owned)

For every endpoint, the backend should have at least one test asserting the response validates against these types (shared example JSON where available, OD-3).
